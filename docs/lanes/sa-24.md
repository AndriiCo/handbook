# Lane SA-24 `commerce` (MISSION WIN)

Read first: `docs/lanes/mission-lanes.md` (shared rules, hooks, ready
protocol, trains), `docs/lanes/contracts.md` + `docs/lanes/contracts/`,
and `docs/ops/mission-win.md` sections D (commerce) and F. Branch `sa-24/commerce`.
Commits `sa-24-<n>`.

## Goal
Customers buy what the plan tells them to do: orders with a backing
submission, Stripe hosted Checkout, a webhook and reconciler that never
double-charge, automatic refunds on carrier failure, the kit queue, and
the staff order API.

## You own (touch nothing else)
- `crates/web/src/{orders,stripe,reconcile,fulfilment,admin_orders}.rs`
- `crates/web/src/p2.rs`: only to make `caller_customer_ref` `pub(crate)`
  (and the `P2Owners` lookup for order shipments if needed)

## Steps, in order (estimate; train)
1. **C1** (5h; T1 dark): p2 tables `customer_order` (id `ord_` + 10
   unguessable chars, customer_ref, kind, status, authority_slug, path_id,
   amount_json, mode, created/updated), `order_shipment(order_id,
   shipment_id, role)`, `order_event`; the state machine (contracts.md
   enumerations) as a pure module with exhaustive tests; every order
   creates one backing `form_submission` (real or a draft shell) and every
   leg's `shipment` row references it (`foreign_keys=ON` test);
   `GET /orders/options` from accepted facts only (USPS-only from a cited
   PO box / "USPS only"; paid disabled without an accepted address; seed
   `order-options.json`); `POST /orders`, `GET /orders`, `GET
   /orders/{id}`; sign-in required; cross-customer authz tests; events on
   `billing:{customer_ref}` and `ops`. Paid tiers 503 `paid_tiers_paused`
   while `orders.enabled` is false.
2. **C2** (6h; T2): quote (SA-25 rate fns + `orders.*` fees); Stripe
   Checkout over ureq (Idempotency-Key, pinned API version, metadata
   order id); webhook on the public router (raw body, HMAC via aws_lc_rs
   like `crates/auth/src/meta.rs:182`, tolerance, `stripe_event` dedupe,
   server-side session re-fetch: amount, paid, livemode); reconciler
   (`reconcile::spawn`, like `follow::spawn_worker`) + `POST
   /orders/{id}/confirm`; refunds (idempotent) on a carrier 4xx from
   SA-25's ledger; mode coherence (test keys ↔ sandbox/TEM only; demo
   sessions never pay live; daily cap; max order).
3. **C5** (5h; T3): fulfilment queue + packet PDF (filled form, checklist
   from the accepted plan, labels; `render_packet_cover` as-is) + admin
   order API (list, detail, refund, advance) per the route table.

## Proof specific to this lane

unreachable for webhooks): order → Checkout → paid → labels (SA-25
sandbox) → events; signature/staleness/replay/amount/livemode tests; the
ledger never double-buys.
