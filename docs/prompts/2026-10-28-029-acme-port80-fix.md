## Response

Context: the 028 train enabled `acme.enabled` in prod; every Google
order went `Invalid` within seconds and systemd restart-looped the
binary ~60x (site down, failed-validation rate limits burning).
Operator stopped the loop and re-pinned the surviving file pair
(`/var/lib/apostille/tls/`) — service restored on the old
`andrii.ai`-only cert.

Root cause (code, not ops): `serve_acme` called
`ensure_certificate()` BEFORE binding any listener — port 80
(redirector + `/.well-known/acme-challenge/`) only started inside
`serve_tls` after issuance succeeded. CA validation fetches hit a
closed port: chicken-and-egg, never live-tested against a real CA.

Fix (`crates/web/src/main.rs`):

- New `spawn_challenge_servers()`: binds std `TcpListener`s on
  every bind IP's `net.http_port` (fail-fast on bind error),
  serves `redirect_router` via `axum_server::from_tcp`, fails the
  process if a listener dies later (protects renewals), returns
  bound addrs + shutdown handles.
- `serve_acme` calls it FIRST, passes handles into `serve_tls`,
  which skips its Redirect plan entries and adds the handles to
  the graceful-drain set. New `serve_tls` param
  `prebound_redirect: Option<Vec<Handle>>`; file-cert path passes
  `None` (unchanged behavior).
- `#[allow(clippy::too_many_arguments)]` on `serve_tls` (8 args;
  precedent: `p2_labels.rs`, `publish`).
- Regression test `challenge_servers_serve_tokens_over_tcp`:
  ephemeral loopback bind, real TCP GETs — token hit (200+body),
  token miss (404), redirect fallback (308+Location). Needs
  `multi_thread` flavor (blocking client would starve the server
  task on current-thread — found by a 60s+ hang).

Dropped: deep Invalid-order diagnostics in `crates/acme` —
`instant-acme` caches authz state, so post-failure refetch returns
stale data; no honest fresh detail available.

Ops guards:

- `docs/ops/apostille.service`: `StartLimitIntervalSec=600` /
  `StartLimitBurst=5` (park the unit after 5 fast failures instead
  of hammering the CA); fixed the stale "no outbound connections"
  comment (ACME needs outbound 443).
- `docs/ops/acme.md`: documented the load-bearing :80-first boot
  order + incident/troubleshooting entry (incl. `rateLimited`
  wait-out guidance).

Verification: `cargo xtask ci` green offline (366 Rust tests pass
— 365 + the new one; secrets-scan clean; clippy `-D warnings`
clean), `web-budget` 212202 < 225280, `cargo zigbuild --release
-p web -p xtask --target x86_64-unknown-linux-gnu` produced Linux
x86-64 ELFs. Note: cargo hung on network this session (registry
fetch stall); all cargo invocations ran with `CARGO_NET_OFFLINE=true`
/ `--offline` against the warm cache.
