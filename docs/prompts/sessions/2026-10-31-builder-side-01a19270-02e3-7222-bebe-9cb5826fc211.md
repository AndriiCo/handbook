#### By day 10: pull-based inference pool

Workers check out jobs; the server never pushes. Design in five pieces:

1. **Queue on the main server** (Rust, new table or JSON store): jobs have `id`, `task`, `payload` (image ref or capture id), `requirements` (min VRAM, model), `state` (`queued → leased → done/failed`), `lease_until`, `attempts`.


How it resolves: `sops` walks up from the target file to find the nearest `.sops.yaml`, matches `path_regex`, and uses that rule's recipient. So future scripts need zero key handling — just `sops decrypt <file>`.

- **Scope**: `~/.sops.yaml` in home covers everything under home. If you later want different recipients per directory (e.g. one key for tokens, another for pool worker keys), drop additional `.sops.yaml` files in those directories — nearest wins.
