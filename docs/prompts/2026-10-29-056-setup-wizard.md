## Response

Built and drilled the setup wizard end to end (work commit
`b2489a1`). Author direction (asked before speccing, recorded
D43–D45): v1 is all-manual with guides (no provider OAuth —
Gmail login stays a future step); the setup key is CLI-minted
and sealed in the DB, hash-only; the setup window needs no
mTLS cert (key alone, closes permanently at burn).

Spec: `docs/specs/secure-config.md` §9 (status APPROVED) +
backfilled D39–D42 in `docs/specs/README.md`. Two read-only
researchers drafted the provider guides in parallel (auth+mail,
infra+voice+postage; ~3.7k words recovered from session logs
after truncated delivery); the parent verified every asserted
default against `RuntimeConfig::default` and the portal docs,
fixed five wrong ones (dev paths, loopback bind, telnyx/gmail
base URLs, a nonexistent `net.quic_port`), and trimmed the
drafts into `setup-guides.js`.

Server (`crates/web/src/setup.rs`, new):

- `setup.key_hash` registry key (57th, Secret); `SetupAuth`
  extractor (`x-setup-key` header, SHA-256 + constant-time
  compare inside the config crate so secret bytes never reach
  the web layer, 30/60 per-IP budget, `setup.denied` /
  `setup.rate_limited` audits); never grants AdminAuth.
- `GET setup/status` (public boolean), `GET setup/steps`
  (wizard rows, `setup.*` filtered), `POST setup/keys/{key}`
  (registry-only sealed put + audit, actor `setup`).
- Enrol setup-mode: the key replaces invite + cert while the
  window is open; first staffer is always admin; refusals
  reuse the gone shape (no oracle); finish re-verifies and
  burns BEFORE ceremony verify (consume-before-persist;
  races fail closed, re-mint is the recovery).
- Admin PUT refuses `setup.*` (422); `csrf_guard` exempts
  `/admin/setup/` (no cookies can exist; handlers enforce
  Origin + the custom header is CSRF-safe by construction).
- `xtask setup-key-mint` (prints `setup_`+64hex once,
  hash-only sealed store, refuses when live staff passkeys
  exist unless `--force`; re-mint overwrites = invalidates).

UI (admin build only):

- `/admin/config` dual-mode: setup key entry → 8 guided
  steps (site, certs, staff, login, models, voice, mail,
  postage) with per-field hints + numbered retrieval guides
  → review (27 required keys, missing-jump list) → enrol
  link. Key in page memory only; secrets write-only both
  modes; normal staff list byte-preserved.
- Enrol `?setup=1` mode (key input, closed-window state,
  lands back on config); layout exempts `/admin/config`
  while the window is open.
- `setup-guides.js` coverage test pins all 56 wizard keys —
  a future registry key without a slot fails loudly.

Live loopback drill (fresh store, real binaries, curl): mint
→ status true → 401/403 gates → sealed text+secret saves →
`setup.*`/unknown 422s → enrol/start returns admin challenge
(no cert) → bogus finish 422s AND burns (status false,
`setup.burned` audited) → re-mint reopens, old key 403s →
mint refuses with a staff row present, `--force` overrides.
Rate limit observed (429 after spray). Full ceremony success
needs a real authenticator — staging-manual per §9.6.
